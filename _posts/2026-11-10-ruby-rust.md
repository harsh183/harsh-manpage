While most people come into Rust from a background of c++, systems programming, low latency, and tight memory environments, I came here after most of my life learning Ruby and being drawn to the elegance it came with. I know much of this is strictly inspired by Ruby, but I am encountering so much Rust syntax that makes me feel quite at home.

## Implicit Returns

One of my favorite things about ruby is small functions not needing an explicit `return` keyword which felt so neat and natural.

Rust:
```rs
fn add(x: i64, y: i64) -> i64 {
    x + y
}
```

and similar ruby:
```rb
def add(x, y)
  x + y
end
```

## Using Expressions On Assigment

This one is quite minor but I've really liked this because I don't have to keep declaring variables outside an if/switch block 

Rust:
```rs
let score = 43;
let grade = if score == 50 {
    "Pass"
} else {
    "Fail"
};
```

Ruby:
```rb
score = 43
grade = if score > 50
  "Pass"
else
  "Fail"
end
```

## Switch flow with `match`

I love having a neat switch case like flow that avoids the C style fall through errors

Rust with `match` and compiler even ensures my ranges don't overlap
```rs
let score = 42;
let grade = match score {
    50.. => "Pass",
    42 => "I'll make an exception",
    _ => "Fail"
};
```

Ruby with `case` and `when`
```rb
score = 42
grade = case score
        when (50..)
          "Pass"
        when 42
          "I'll make an exception"
        else
         "Fail"
        end
```
## Range syntax using `..`

Being able to `start..end` ranges has always been so cute, and even nicer seeing unbounded also work.

Rust:
```rs
let exclusive_range = 1..3;
assert_eq!(1+2, exclusive_range.sum());

let inclusive_range = 1..=3;
assert_eq!(1+2+3, inclusive_range.sum());

let unbounded_range_end = 100..;
let unbounded_range_start = ..99;
println!("{:?} {:?}", unbounded_range_end, unbounded_range_start);
```

Ruby:
```rb
exclusive_range = 1...3
inclusive_range=1..3
puts "1 + 2 = #{exclusive_range.sum}"
puts "1 + 2 + 3 = #{inclusive_range.sum}"

unbounded_range_end = 100..;
unbounded_range_start = ..99
puts "#{unbounded_range_end} #{unbounded_range_start}"

# yes on rare occasions ruby does need ;, we could also use () to wrap or explicitly set `nil` as the end but the issue here is ruby is looking on the next line for the range end
```

Note that the ruby and rust inclusive and exclusive are a flipped here, and there was quite a bit of debate around this [back in the day](https://internals.rust-lang.org/t/vs-for-inclusive-ranges/1539/4)

Also interestingly, some versions of rust allow `...` similar to ruby having `...`, but only [in expressions](https://stackoverflow.com/questions/49834574/why-it-is-not-possible-to-use-the-syntax-in-expressions) and with some deprecation warnings suggesting using `..=` which does honestly read better imo.

```rs
let age = 26;
match age {
    0...26 => println!("still cool"),
    _ => println!("unc"),
}
```

## Nice Higher Order Helpers

I really got used to having nice higher order functions that work like `map`/`filter`/`reduce` and rust feels just at home

Rust
```rs
let nums = vec![1, 2, 3];
let odd_sq_product = nums.into_iter()
    .filter(|item| item % 2 == 1)
    .map(|item| item*item)
    .fold(1, |acc, item| acc * item);
```

Ruby
```rb
nums = [1, 2, 3];
odd_sq_product = nums.select {|item| item % 2 == 1}
  .map {|item| item * item}
  .reduce {|acc, item| acc * item}
```
